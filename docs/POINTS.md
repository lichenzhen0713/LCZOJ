# LCZOJ 积分系统说明

> 本站积分由 **基础分、练习分、比赛分、社区分** 四个维度组成，满分 **400**。
> 本文说明每一项的完整计算规则、参数、衰减与示例，便于用户理解积分来源，也便于二次开发调参。
>
> 相关代码：`src/users.js` 的 `computePoints()` 与常量 `POINTS_WEIGHTS`；实时榜单 `src/contest.js` 的 `computeStandings()`；等级分 `src/rating.js`。

---

## 一、总览

```
总分 = round(基础分) + round(练习分) + round(比赛分) + round(社区分)
```

- 四个维度各自先算出**小数**，**分别四舍五入**后相加，所以总分是整数，且**每项最多 100 分**（合计上限 400）。
- 积分为**实时计算**：不落库、无缓存，任何时候打开个人中心看到的都是当前值。
- 结果会以 `{ total, breakdown: { base, practice, contest, community } }` 的形式返回，页面上可以直接看到四维明细。

| 维度 | 满分 | 主要来源 | 是否随时间衰减 |
| --- | --- | --- | --- |
| 基础分 | 100 | 账号本身（违规会扣） | 违规扣分随时间部分恢复 |
| 练习分 | 100 | 题库（非赛时）AC 的**题目数**、连续性、难度 | 长期不刷题会衰减（保底 10） |
| 比赛分 | 100 | 有效参赛场次的**名次**与**场次数量** | 长期不参赛会衰减（最高扣 90%） |
| 社区分 | 100 | 题解/专栏、讨论、回复、被赞 | 长期不活跃会衰减（保底 20） |

## 二、基础分（100 分起）

| 情形 | 效果 |
| --- | --- |
| 正常账号 | **100** |
| 棕名（抄题解 `plagiarism` / 比赛作弊 `cheat`） | **−50** |
| 账号被封禁（`banned`） | **直接为 0** |
| 被撤销权利（禁言 / 禁发题解），每项 | **−20**，并按时间恢复 |

**权利恢复曲线**（决定那 −20 分什么时候还给你）：

| 距撤销的时间 | 已恢复比例 |
| --- | --- |
| 0 天 | 0% |
| 90 天 | 50% |
| 365 天 | 93% |
| 之后 | 保持 93%（不会完全恢复） |

- 撤销时间取管理日志（`moderation_logs`）中最近一次 `revoke_speak` / `revoke_editorial` / `ban` 的时间；取不到时按"30 天前"估算。
- 基础分**不会**低于 0。

## 三、练习分（0 ~ 100）

只统计**题库提交**（`contest_id IS NULL`）中**判定为 Accepted** 的题目，且**按题目去重**（同一题重做不重复计分）。

### 1. 基础刷题分（对数边际递减）

设去重后的 AC 题数为 `n`：

```
基础刷题分 = Σ (i = 1 → n) 1 / (1 + 0.05 × (i − 1))       上限 100
```

含义：第 1 题贡献 1 分，第 2 题 0.952 分，第 11 题 0.667 分，第 21 题 0.5 分……**越到后面单题收益越低**，鼓励做难题而不是反复水简单题。

| 题数 | 基础刷题分（约） |
| --- | --- |
| 1 | 1.00 |
| 5 | 4.56 |
| 10 | 8.50 |
| 20 | 15.24 |
| 50 | 30.53 |
| 100 | 45.19 |
| 300 | 72.66 |
| 1000 以上 | 逼近 100 |

### 2. 连续性系数（鼓励每天来）

设**连续刷题天数** `d`（从今天往前逐日回溯，每天至少 1 道题库 AC；今天没做则从昨天开始数）：

```
d = 0  → 0.5
d > 0  → 0.5 + 0.5 × (1 − e^(−d / 14))
```

| 连续天数 | 系数 |
| --- | --- |
| 0 | 0.50 |
| 1 | 0.53 |
| 3 | 0.60 |
| 7 | 0.70 |
| 14 | 0.82 |
| 30 | 0.94 |
| 60+ | ≈1.00 |

### 3. 难度惩罚（防止只刷水题）

取**近 7 天**题库 AC 的**平均难度系数**：

| 题目难度 | 系数 |
| --- | --- |
| 1（入门） | 0.4 |
| 2（普及−） | 0.6 |
| 3（普及/提高−） | 0.8 |
| 4（提高+/省选−） | 1.0 |
| 5 | 1.2 |
| 6 | 1.5 |
| 7 | 2.0 |

```
难度惩罚 = min(1.0, 平均难度系数)     // 高于 1.0 不再加成，低于 1.0 会打折
```
近 7 天没有 AC 记录时按 **1.0** 处理。

### 4. 练习分

```
练习分 = 基础刷题分 × 连续性系数 × 难度惩罚      上限 100
```

### 5. 衰减与保底

- 若**近 7 天**题库 AC 数为 0，且距最后一次 AC **超过 2 周**，则按 S 型曲线衰减：

```
inactiveWeeks = (今天 − 最后一次 AC) / 7 天
decay = min(1 − 1/(1 + e^(inactiveWeeks − 4)), 0.85)
练习分 = 练习分 × (1 − decay)
```
 即：**最高扣 85%**，不会全部扣光。
- 超过 **365 天**没有题库 AC：练习分**保底 10 分**。

## 四、比赛分（0 ~ 100）

### 1. 哪些比赛算"有效场次"

同时满足以下条件的比赛才计入：

1. 你**报名**了这场比赛；
2. 在**比赛时间窗口内**（`start_time ≤ 提交时间 ≤ end_time`）至少有一次提交；
3. 比赛**已经结束**；
4. 你**没有**被该场比赛判定作弊（`contest_penalties` 中没有你的记录）；
5. **Rated 比赛必须已经结算等级分**（`ratings_applied = 1`，即管理员已完成"计算等级分"）；
   不评级（`rated = 0`）的比赛不受此限制，结束后即计入。

> 也就是说：比赛刚结束时**不会立刻**产生比赛分，需要等该场完成等级分结算后才会计入。

### 2. 名次如何取

- 名次以**实时榜单**（`computeStandings()` 纯函数）为准，不依赖旧快照；
- 参赛人数取「**报名人数**」与「**实时榜单中实际占名次人数**」的**较大值**，避免出现 `名次 > 人数` 导致百分位失真；
- 名次取不到时按**末位**处理（不会误当第一名）。

### 3. 单场贡献

设这场比赛在你所有有效场次中按结束时间升序的序号为 `idx`（从 0 开始）：

```
场次权重  base       = 2 / (1 + e^(−(idx + 1) / 10)) − 1
名次系数  rankFactor = 按百分位 percentile = rank / 参赛人数
```

| 百分位 | 名次系数 |
| --- | --- |
| ≤ 1%（前 1%） | **1.8** |
| ≤ 5% | 1.5 |
| ≤ 10% | 1.2 |
| ≤ 25% | 1.0 |
| ≤ 50% | 0.8 |
| ≤ 75% | 0.5 |
| > 75% | 0.3 |

```
频次系数  freqFactor = 0.5 + 0.5 × min(1, 近 30 天参赛场次 / 5)
单场贡献             = base × rankFactor × freqFactor
```

`base` 随 `idx` 递增（越靠后的场次权重略高），上限趋近 1.0：

| idx | 0 | 1 | 2 | 3 | 5 | 10 | 20 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| base | 0.050 | 0.100 | 0.149 | 0.197 | 0.291 | 0.462 | 0.689 |

### 4. 比赛分

```
比赛分 = min(Σ 单场贡献 × 100 × 0.15, 100)
```
`0.15` 是整体压缩系数（`POINTS_WEIGHTS.contestScale`），避免少数几场就把比赛分打满；场次多、名次好才能明显涨分。

### 5. 衰减

- 距**最近一次有效参赛**超过 **30 天**开始衰减（幂律曲线），**最高扣 90%**；
- 名次很差（`rankFactor 0.3`）时，单场贡献本身就很小，比赛分自然偏低。

## 五、社区分（0 ~ 100）

社区互动分四类累加。**前三类（帖子 / 回复 / 点赞）单次最多加 1 分**，防止用少量互动把社区分迅速推高。

### 1. 题解 / 专栏（唯一没有"单次 1 分上限"的项）

第 `idx` 篇（按时间排序，从 0 开始）：

```
单篇基础      base        = 12 / (1 + 0.05 × idx)
连续创作系数  contFactor  = 连续创作篇数 = 0 时 0.5
                           否则 0.5 + 0.5 × (1 − e^(−连续篇数 / 5))
篇幅系数      lengthFactor= 按字数：<500 → 0.6；<1000 → 0.75；<2000 → 0.9；<5000 → 1.0；否则 1.2
单篇贡献                  = min(base × contFactor × lengthFactor, 8)
```

> "连续创作"按最近连续发表的文章数计算（没有文章时为 0）。单篇贡献**封顶 12 分**（乘社区系数后最多 19.2 分）。

### 2. 讨论主题帖

```
第 idx 个帖子贡献 = min(2.0 / (1 + 0.15 × idx), 1 / 1.6)
```
- 第 1 个帖子：**1.00 分**（缩放后）
- 越靠后的帖子递减，且**每次都不超过 1 分**

### 3. 讨论回复

```
第 idx 条回复贡献 = min(0.6 / (1 + 0.2 × idx), 1 / 1.6)
```
- 第 1 条：0.96 分，之后递减，**每次不超过 1 分**

### 4. 题解 / 专栏被赞

```
被赞贡献 = min(被赞次数 × min(0.5, 1 / 1.6), 20)
```
- **自赞不计**；
- 每次被赞 **0.8 分**；
- 「被赞」这一个子项整体**上限 20 分**（防互刷）。

### 5. 社区分与衰减

```
社区分 = min(Σ 上述四项 × 1.6, 100)      // 1.6 = POINTS_WEIGHTS.communityScale
```

- 距**最近一次社区活动**（发文章 / 发帖 / 回复 / 被赞）超过 **30 天**开始衰减（幂律），**最高扣 80%**；
- 超过 **365 天**没有社区活动：社区分**保底 20 分**。

## 六、计算示例

### 示例 A：刚注册不久的新人

假设：无违规；题库 AC 5 道题（难度 1~2），连续刷题 3 天，近 7 天平均难度系数 0.6；没参加比赛；没发帖。

| 维度 | 计算 | 结果 |
| --- | --- | --- |
| 基础分 | 正常账号 | 100 |
| 练习分 | `4.56 × 0.596 × 0.6 = 1.63` | **2** |
| 比赛分 | 无有效场次 | 0 |
| 社区分 | 无社区行为 | 0 |
| **总分** | 100 + 2 + 0 + 0 | **102** |

### 示例 B：活跃用户

假设：无违规；题库 AC 60 题、连续 30 天、近 7 天平均难度 1.0；参加 6 场有效比赛且名次都在前 25%、近 30 天参赛 4 场；发表 3 篇文章（1500 / 2500 / 800 字）、5 个帖子、20 条回复、被赞 30 次。

| 维度 | 计算 | 结果 |
| --- | --- | --- |
| 基础分 | 正常账号 | 100 |
| 练习分 | `27.48 × 0.941 × 1.0 = 25.86` | **26** |
| 比赛分 | `Σ 单场 0.929 × 100 × 0.15 = 13.93` | **14** |
| 社区分 | 文章 19.53 + 帖子 3.13 + 回复 5.08 + 被赞 15 = 42.74，`× 1.6 = 68.38` | **68** |
| **总分** | 100 + 26 + 14 + 68 | **208** |

## 七、参数速查（`src/users.js` → `POINTS_WEIGHTS`）

| 参数 | 默认值 | 作用 |
| --- | --- | --- |
| `contestScale` | `0.15` | 比赛分整体压缩系数 |
| `contestTopFactor` | `1.8` | 前 1% 名次的加成 |
| `communityScale` | `1.6` | 社区分整体放大系数 |
| `articleWeight` | `12` | 每篇题解/专栏基础权重（也是单篇上限） |
| `discussionWeight` | `2.0` | 讨论主题帖基础权重（受"单次 ≤1 分"限制） |
| `replyWeight` | `0.6` | 讨论回复基础权重 |
| `likeWeight` | `0.5` | 每次被赞权重 |
| `likeScoreCap` | `20` | 「被赞」子项整体上限 |
| `communityPerItemCap` | `1` | **社区互动单次加分上限（帖子 / 回复 / 点赞）** |

其他可调常量（在 `computePoints()` 内部）：练习分的递减系数 `0.05`、连续性半衰期 `14` 天、题量衰减宽限 `2 周` / 上限 `85%`、比赛名次各档系数、社区衰减宽限 `30 天` / 上限 `80%` 等。

## 八、常见问题

**Q：为什么我打了比赛，比赛分还是 0？**
1. 比赛可能还没结束；
2. 你可能没有在该场比赛的时间窗口内提交；
3. Rated 比赛需要管理员完成"计算等级分"结算后才计入比赛分（在后台比赛管理里操作）；
4. 如果该场判定你作弊，整场不计入。

**Q：为什么刷了很多题，练习分涨得很慢？**
练习分看的是**去重后的题数**而不是提交次数，且单题收益递减；连续刷题和题目难度会显著影响最终值。

**Q：为什么发了帖子，社区分几乎没变？**
帖子 / 回复 / 点赞**每次最多 1 分**（缩放后），且越靠后递减；社区分的主要来源是**题解与专栏**（单篇最高 12.8 分）。

**Q：为什么积分会掉？**
长期不活跃会衰减：练习分最高扣 85%（保底 10）、比赛分最高扣 90%、社区分最高扣 80%（保底 20）。基础分只在违规时扣，并随时间部分恢复。

**Q：积分能不能手动改？**
不能。积分是**实时算出来的**，数据库里没有积分数值字段，因此不存在"改分"入口；要调整规则只能修改 `src/users.js` 里的参数与公式。
