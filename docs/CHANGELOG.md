## v2.8.6

- **修复默认网站图标"改了也不生效"**：根因是默认图标的地址一直是同一个 URL，**浏览器（Chrome/Edge 的图标缓存）不会重新下载**，于是本机一直显示很早以前的空白图标。现在默认地址带上版本号（`/api/favicon?v=…`），换图标后浏览器会重新取；并新增 **`/favicon.ico` 兜底**（以前是 404），老标签页、书签、以及"没有可用图标"的场景也能拿到图标。

## v2.8.5

- **「积分计算」改为「功能设置」的二级页面**：在「系统设置 → 功能设置」页顶部新增「积分计算」入口，点进去是独立页面（面包屑「功能设置 / 积分计算」，父项「功能设置」一键可回）；旧地址会自动跳转到新地址，不留死链。页面功能不变（实时 / 定时自动 / 手动结算、间隔小时·天、状态信息、立即结算）。

## v2.7.6

- **修复「一键更新」失败**：个别网络环境下，更新源会返回"需要登录"的网页，旧版本把它当成源码包，只提示「不是有效的 ZIP 文件」。现在会识别出这不是更新包并**自动换其它源**，失败时给出可读原因。
- **更新前先检查权限**：只读部署（例如 systemd 的系统保护）会在**下载之前**就明确告诉你"请在服务器上用命令行更新"，不再下载解压一半才失败。
- **更新过程可回滚**：写入前自动快照，中途出错会**把改过的文件全部还原**，不会留下更新的半成品。
- **重启更可靠**：只结束本项目自己的服务进程（不会误杀其它程序），重启后会**真实核实健康检查**，不再出现"提示更新成功、其实还是旧版本"的情况。
- 同时支持**没有顶层目录的更新包**；命令行 `node deploy/update.js` 与后台更新走同一套逻辑，失败原因与解决办法都会打印出来。
