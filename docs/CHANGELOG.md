**变更（部署体验）：Docker / 面板部署显示公网地址；初始管理员密码改为随机生成**
- **公网地址**：Docker（`docker-bootstrap.sh`、`deploy/docker-onekey.js`）与面板脚本以前打印的是 `hostname -I` 取到的**内网 IP**，云服务器上用户照此访问必然打不开。现改为：
  - 新增共用模块 `deploy/net-info.js`：`internalIp()` / `publicIp()` / `siteUrl()` / `initialAdminPassword()`；
  - 公网 IP 依次查询多个公开源（`ip.3322.net` → `myip.ipip.net` → `ifconfig.me/ip` → `ipinfo.io/ip` → `api.ipify.org` → `ident.me` → `4.ipw.cn`），**严格校验四段 0~255、拒绝前导零、拒绝超长（HTML）响应**，避免误取页面里的其它数字；可用 `LCZOJ_PUBLIC_IP` 直接指定；
  - 输出改为「公网地址（外网用这个）+ 内网地址（局域网用这个）+ 云服务器安全组放行端口提示」，识别失败时明确提示用公网 IP 或指定环境变量；
  - `server.js` 启动横幅在容器内（检测 `/.dockerenv`）额外提示「用宿主机公网 IP 访问、注意端口映射与安全组」。

  - 可用环境变量 `OJ_ADMIN_PASSWORD` 指定（< 6 位时会提示并回退随机）；
  - 启动横幅**在创建的那一次**打印初始密码，并说明落盘位置；后续启动只提示「沿用数据库中已有的密码」以及初始密码记录文件的位置（不再重复打印密码）；

**优化：SPJ checker 编译缓存（不再每次评测都编译）**
- **问题**：判题机虽然按「checker 源码哈希」缓存过编译产物，但每次评测结束都会**把本次编译出的 checker 删掉**（`releaseSubmissionCheckers()`），
  且启动/定时的 `cleanSpjCache()` 会**整目录清空** `data/spj_cache` —— 结果是**每一次 SPJ 提交都要重新编译一遍 checker**。
  在本机实测：单次 checker 编译耗时 **17~36 秒**，同一道题的每份提交都要白付这笔开销。
- **修复**：
  1. **保留编译产物**：评测结束只解除占用（`releaseSubmissionCheckers()` 改为仅取消 in-use 记录 + 清理中断残留的 `*.tmp`），
     编译好的 checker 留在 `data/spj_cache/checker_<源码哈希>.exe` 下，后续评测直接命中复用；
  2. **失效判断**：缓存键 = checker 源码 + 实际使用的 `testlib.h` 内容 + 编译参数（`-fno-asm -std=c++14 -O2`），
     任一变化即哈希变化 → 自动重新编译（改动 checker 后不会误用旧产物）；命中时校验文件非空，空文件视为无效并重建；
  3. **命中即跳过编译**：命中缓存时更新文件访问时间（用于按「最近使用」淘汰）并写日志
     `[OJ] SPJ checker 命中编译缓存（题目 #N），跳过编译`；首次编译则记录 `编译完成并写入缓存（题目 #N，<耗时>ms）`；
  4. **有界缓存**：新增 `pruneSpjCache()` 取代原来的「整目录清空」——按最近使用时间保留最新 **30** 个条目，
     并淘汰 **30 天**未使用的条目，始终跳过正在运行的 checker；每次新编译后与启动/每 10 分钟维护时各执行一次。
- **效果**：同一道题的 SPJ，**checker 只编译一次**，之后每份提交都省下 17~36 秒的编译时间（本机实测）。
- **验证**（真实提交 + 服务端日志，14 项断言）：
  - 清空缓存后第 1 次提交：日志 `编译完成并写入缓存`、判 **Accepted**、缓存出现 1 个可执行文件（>10 KB）；
  - 第 2 次提交：日志 `命中编译缓存…跳过编译`（**不再编译**）、仍判 **Accepted**、缓存条目数不变，总耗时明显低于第 1 次；
  - 错误答案提交仍正确判 **Wrong Answer**（复用同一缓存）；
  - 改动 checker 源码后：自动重新编译并新增缓存条目（2 个）、判定仍正确；**还原 checker 后命中原来的缓存条目**（不再新增）；
  - 淘汰逻辑：造 42 个条目（含过期时间戳）→ `pruneSpjCache()` 后剩 30 个，真实使用中的条目被保留；
  - 收尾：checker 已还原为原内容、题库仍为 18 题、测试产生的缓存已清理。
- 文档：`docs/USAGE.md`（SPJ 一节）与 `docs/CUSTOMIZATION.md`（SPJ 编译说明）补充「checker 只编译一次、按哈希缓存、超量/过期自动淘汰」的说明。

**修复：install.bat 调用 winget 时使用了不存在的参数**
- **现象**：`install.bat` 自动安装编译器阶段，每个未安装的语言都输出
  `当前命令无法识别参数名称: "--progress-bar"`，随后被记为「自动安装失败（错误码 …）」，编译器一个也装不上，用户只能手动下载。
- **根因**：脚本第 154 行使用 `winget install --id <包ID> --silent --accept-package-agreements --accept-source-agreements --progress-bar`。
  **winget 从来没有 `--progress-bar` 参数**（它自身就会显示下载进度），传入未知参数会在参数解析阶段直接失败并中断该次安装。本机 winget v1.29.380 复现结果与用户报错完全一致：
  ```
  winget install --id ... --progress-bar   →  当前命令无法识别参数名称: "--progress-bar"   （退出码 1）
  ```
- **修复**：改为 `winget install --id <包ID> --exact --silent --accept-package-agreements --accept-source-agreements --disable-interactivity`

## v2.0.5 · 2026-10-03

> 修复缺陷：Linux（systemd）部署下，管理后台一键更新在重启阶段报
> 「systemd 重启失败（需要 root 权限）」，并因此把整次更新判定为失败（实际上代码已经更新完成）。

**修复：systemd 部署自动更新无法重启服务**
- **现象**：更新到重启阶段时界面显示「更新失败：systemd 重启失败（需要 root 权限）：…」，用户无法判断代码到底有没有更新。
- **原因**：重启逻辑只要发现存在 `lczoj.service` 单元就直接执行 `systemctl restart lczoj`；而 systemd 托管的服务通常以普通用户（如 `www`）运行，该用户无重启权限，命令失败后代码直接抛出异常，被上层当作「更新失败」。此外原判定只看「单元文件是否存在」，未核对当前进程是否真的由该单元启动。
- **修复**：
  1. **重启方式判定改为核对进程号**：PM2 需为「当前进程即该应用进程」，systemd 需为「单元处于激活状态且单元 `MainPID` 就是当前进程」，避免手工启动的实例被错误交给 PM2 / systemd 重启（否则会出现两个实例争抢端口）；
  2. **权限回退**：非 root 时先执行 `systemctl restart lczoj`，失败后自动尝试免密 sudo `sudo -n systemctl restart lczoj`（`-n` 保证无权限时立即失败、不会卡住等待输入密码）；
  3. **区分「更新失败」与「需要人工重启」**：两条命令都失败时不再判定更新失败 —— 代码更新已完成，界面与命令行提示「代码已更新完成，请手动执行：`sudo systemctl restart lczoj`」，并列出每条命令的失败原因；
  4. 判定逻辑抽成纯函数 `decideRestart()`、执行逻辑抽成可注入 runner 的 `performRestart()`，便于覆盖各种启动方式与权限组合的测试。
- **新增 `deploy/grant-restart-permission.sh`**（执行一次即可让后台自动重启）：自动识别服务运行用户（读取 `systemctl show -p User` 或单元文件 `User=`，其次项目目录属主），写入 `/etc/sudoers.d/lczoj-restart`，**仅授予**该用户对 `lczoj` 服务的 `restart / start / stop / is-active` 权限；写入后用 `visudo -cf` 校验语法，不通过立即回滚；支持 `--user` 指定用户、`--unit` 指定单元、`--remove` 撤销。

**界面**
- 管理后台 → 系统设置 → 版本更新：新增「代码已更新但需要手动重启」提示条，显示可直接复制的重启命令，并提示可执行 `sudo bash deploy/grant-restart-permission.sh` 以后自动重启。

**文档**
- `docs/UPDATE.md`：重启行为对照表补充判定依据、新增「4.2 systemd 部署：重启权限」小节（三步处理流程 + 授权脚本用法）；常见问题新增该场景条目；相关文件清单补充授权脚本。

**验证**（单元测试 15 项全通过，真实运行环境为 Windows 无 systemd，故以可注入的纯逻辑测试覆盖 Linux 场景）
- 判定逻辑 9 项：PM2 且 PID 一致 → pm2；存在同名 PM2 应用但 PID 不符 → 不交给 PM2；systemd 激活且 MainPID 一致 → systemd（非 root 标记 needsSudo、root 不标记）；单元激活但 MainPID 不符（手工启动）→ 不交给 systemd；单元未激活 → 不走 systemd；存在 `panel.pid` → pidfile；无守护 → helper。

**修复：Markdown 渲染死循环（严重，会让整个服务端卡死）**
- **现象**：只要正文里出现「**一行含 `|`、紧接着下一行含 `-`**」且这一行不是真正的表格，服务端的段落合并就会一行都不消费、`i` 不前进 → **死循环**：事件循环被占满、CPU 100%、`/api/health` 也不再响应，同时 `out` 数组不断增长（实测失控进程占用到 1.29GB 内存）。这个问题**在本次写面板文档时才被触发暴露**（`  curl … | bash -` 下一行是 `  apt-get install -y nodejs`），但它是**既有缺陷**：用户在题面、讨论、专栏里写「`a|b`」换行「`1-100`」这类内容同样会把站点卡死。
- **根因**：表格分支用的是严格判断（下一行必须匹配 `|---|---|`），而段落合并的结束条件用的是宽松判断（下一行**含 `-`** 就算结束），两者不一致；宽松条件在段落第一行就成立时，段落循环 `push` 0 行、`i` 停滞 → 外层 `while` 永久空转。
- **修复**：抽出统一的 `isTableStart()`（表格分支与段落合并共用同一严格判断，两处不再各写一份）；段落合并改为「**首行必定消费**」，从结构上杜绝 `i` 不前进（即使将来判断再被改错，也只是渲染成普通段落，不会死循环）。
- **顺带修复的两个渲染问题**：
  - **引用块（`> 引用`）此前根本没生效**：块解析入口先把 `<` `>` `&` 转义成实体，而引用块的正则只认字面 `>`，于是引用一律被当普通段落输出。现在同时接受 `>` 与 `&gt;`，`> 注意：…` 这类提示能正常显示成引用框。
  - **列表项里的缩进代码块**（面板文档常见的 `  ```bash`）此前不被识别为代码块（围栏正则要求顶格），现在按 Markdown 规范允许最多 3 个空格缩进，面板 / 部署文档里的命令块能正常高亮成代码块。
  - **表格单元格里的转义竖线 `\|`** 此前被当成列分隔符，导致「`curl … \| sh`」这类内容把整张表撑成多列、排版错位；现在按未转义竖线切分单元格，并把 `\|` 还原成普通竖线（题面 / 讨论里写表格同样受益）。

## v1.20.0 · 2026-10-02

**重构：提交代码框（`public/js/editor.js` 整份重写）**
- **问题（实测）**：粘贴 1200 行 / 71KB 的代码，一次粘贴卡 **6.8 秒**，之后每敲一个字符要 **620ms**；粘贴 6000 行 / 367KB **直接卡死**（120 秒无响应）。长代码还会把代码框**一直撑到底**——6000 行时代码框被撑到 **124,907px**、整页高 **126,307px**。
- **根因**：① 浏览器的插入文本是**逐字符**走的（`execCommand('insertText')` / IME 路径），把 71KB 插进一个**最普通的 textarea** 就要 5.7 秒，而 `textarea.value = 文本` 只要 4.2ms；② 整份代码都塞进高亮层 `<pre>`、且**每行一个行号 `<div>`**，而 `overflow:hidden` 只裁剪绘制、不减少元素自身高度，行号有多少行就把编辑器撑多高；③ 每帧渲染夹着 `clientHeight` / `scrollWidth` 读取，与写 DOM 交替触发强制同步重排。
- **改法**：拦截 `paste` 事件后**一次性赋值**（自带撤销/重做栈，Ctrl+Z 可撤回粘贴，光标自动滚进可视区）；超过 8000 字符或 300 行后**只渲染可视区那几十行**（高亮层与行号都虚拟化，并带上这一屏开头的词法状态，跨行注释与长字符串颜色依旧正确）；**行号列改为绝对定位**、文本框**固定高度**，代码框再也不会被内容撑高；消除每帧强制重排并新增**可拖动的自定义滚动条**（文本框自身滚动条是隐藏的，否则会挤窄文本、与高亮层错位）；连续输入时先写纯文本、停手 ~140ms 后再上色。
- **效果**：粘贴 71KB 处理耗时 **6.8s → 3.4~7.5ms**、367KB **14~31ms**（此前卡死）；渲染开销与文件大小无关（6004 行文件里高亮层只放 2121 字符、行号只放 37 个）；滚动到深处的**高亮错位 19.4px → ≤1.4px**（行高测量改用 300/600 行差值，定位改用比例定位）；代码框高度 **124,907px → 320px**（页面 126,307px → 1,720px）；代码框加大到桌面 **420px** / 手机 **320px**（可拖拽调整）；粘贴后键盘输入、滚动、Tab 多行缩进、Ctrl+Z 全部正常。

- **允许 O2 的题目无法关闭 O2**：提交页的 O2 开关此前是 `<span class="switch">`，而站内开关样式把 `input` 设为透明 0 尺寸，只有 `<label>` 才能点哪儿都切换 —— 结果开关点不动，一直按「开启」提交。现在改为 `<label>`，点击开关/文字即可切换。并用 `__OPTIMIZE__` 宏写了验证题实测：关闭 O2 的提交输出 `O0` → Accepted，开启 O2 的提交输出 `O2` → Wrong Answer（题目期望 `O0`），确认开关真的影响编译参数。
- **长代码输入卡顿/异常**：编辑器此前每次按键都要对全文做正则高亮 + 重建全部行号 DOM。现在改为按帧合并重绘、行号只在行数变化时重建；超过 20000 字符或 800 行自动切换为纯文本模式（顶部提示「已暂停实时语法高亮以保证输入流畅」），超过 20000 行不再渲染行号。实测粘贴 3000 行 / 66779 字符：派发输入事件 11ms、后续输入 9ms，内容完整保留。

**优化（LaTeX / KaTeX 渲染）**
- KaTeX 结果**按公式缓存**（同一公式整个会话只渲染一次），并对元素打 `data-katex-done` 标记，重复调用直接跳过；
- 渲染改为**空闲帧分批**进行（每帧最多 12ms），先让页面画出来，长题面不再卡首屏 —— 实测 120 个公式入队仅 1ms。
- 内置 LaTeX 渲染器补齐常见写法：`\begin{cases}` / `aligned` / `array` 等环境（含 `&` 分列、`\\` 换行）、`\left\{ … \right\}` 等转义定界符、`\% \& \# \_ \{ \}` 转义符与 `\,` `\;` `\!` 间距、`\mathbb` / `\mathcal` 字体命令、`\displaystyle` / `\limits` / `\textstyle` 排版命令、`\overset` / `\underset` / `\stackrel`、`\pmod`、以及 `\div \oplus \otimes \therefore \because \iff \leqslant \varnothing \vdots` 等一批符号（此前会直接把命令名当文字显示）。28 条常见写法的覆盖测试全部通过。

**优化（手机端）**
- 手机端底部导航条不再显示「社区管理」（导航条更清爽），改由右下角圆形按钮进入（电脑端仍走侧边栏）。
